# CIVITAS Phase 3 — Definition of Done

**Contract version:** `civitas-phase3-dod/v1`  
**Status:** `normative promotion gate`

## 1. Evidence levels

```text
A: runtime/code
B: executable contract/schema/migration
C: automated test/gate
D: document/issue
E: deployed/operational evidence
```

A document or closed issue is not E-level evidence.

## 2. Contract DoD

- authority and precedence documented;
- one canonical identity per permission/service/tool/dimension;
- schemas valid and versioned;
- generated outputs reproducible;
- provider-neutral IDs;
- issue traceability complete;
- no unresolved conflict markers or implicit aliases.

## 3. Authorization v2 DoD

- #217 membership authority selected and evidenced;
- token claim allowlist matches the schema;
- principal and role paths are membership-bound;
- revocation/freshness tests pass;
- #218 v2 registries implemented;
- zero active `grade_level`/`section` references;
- DataScopeEvaluationRequest unified;
- complete-path OR and no fragment composition proven;
- closed #161–#166 gates re-run on the v2 SHA.

## 4. Tenant DoD

- trusted host resolution;
- host-only session and CSRF;
- host/session/principal/route/resource equality;
- neutral cross-tenant errors;
- workers/MCP use authenticated tenant context;
- two-tenant E2E and session revocation pass.

## 5. Application service / REST DoD

Per operation:

- service registered and implemented;
- canonical permission active;
- scope strategy explicit and reviewed;
- module/capability available;
- OpenAPI parity passes;
- controller thin, no direct DB/provider business flow;
- list/count/export filtering parity;
- idempotency/concurrency/error semantics tested;
- consumer, deployment, observability and rollback evidenced.

## 6. MCP DoD

Per tool:

- lifecycle at `active` only after approved and planned stages;
- shared runtime and service identity operational;
- principal/delegation/tenant reconciliation passes;
- service parity passes;
- closed bounded schemas and output limits;
- no authority fields, REST loopback or direct DB/provider access;
- R2 confirmation/consent replay tests pass where required;
- rate limits, audit and kill switch active;
- tenant enablement and rollback evidenced.

## 7. Module DoD

- module manifest ownership and lifecycle valid;
- permission/service/REST/UI/event parity;
- runtime binding compatible and healthy;
- degradation behavior safe;
- tenant installation/activation separate from permission grants;
- data owner backup/restore and decommission policy documented.

## 8. Production DoD (#199)

- SLI/SLO and alert thresholds approved;
- correlated telemetry without secrets/PII;
- backup and restore drill with RPO/RTO evidence;
- restore validates tenant and contract hashes;
- circuit, DLQ and reconciliation drills;
- key/service identity rotation;
- canary and rollback executed;
- decommission and zero-consumer evidence;
- residual risk register accepted.

## 9. Issue closure checklist

Every implementing issue records:

```text
Canonical document:
Section:
Contract version:
Depends on:
Produces:
Validates with:
Activation impact:
Rollback:
Repository ref/SHA:
Evidence links:
```

Closure is blocked when required evidence belongs to another branch/SHA or is only self-declared.

## 10. Global no-go conditions

```text
membership binding missing
Data Scope v2 incomplete
REST permission orphan
Data Scope wiring unproven
Tenant Resolution not evidenced for portal
MCP registry/runtime absent for proposed active tools
production evidence missing
```

## 11. Result states

```text
PASS_CONTRACT_STATIC
  package contracts and internal parity pass

PASS_REPOSITORY
  repository implementation and generated outputs pass on one SHA

PASS_PRODUCTION
  operational evidence under #199 passes

NO_GO
  any P0 blocker or required evidence is missing
```

The package generated by these documents may reach `PASS_CONTRACT_STATIC`; it must not claim `PASS_REPOSITORY` or `PASS_PRODUCTION` without executing against the real repository and environment.
